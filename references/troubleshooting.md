# 已验证的问题处理与工程路径

用于已有成片的窄修改、真实失败排查和交接。不是每次都重跑的清单；只加载本轮涉及项。最新用户指令优先于默认，旧交付和证据先保留。

## 现象 → 原因 → 处理 → 证据

| 现象 | 已遇到的原因与处理 | 实际核对 |
| --- | --- | --- |
| 钩子“有网感”却不是用户要的句式 | 从分类重新创作了句子。改用[公开完整库](../assets/copywriting/library.json)，记录原句ID，只填省略号；用户指定成句则逐字采用 | fill_copywriting.py输出、原句与非槽位逐字对照；不把模板数字、经历或效果当事实 |
| 朗读一直加载，没有音轨 | 长文本超过当前音色单次限制。先看字符数和实际用户/UI限制，不直接判定音色不可用；按[有依据的限制分块](jianying-voice-ai-edit.md#单次字数限制有依据才拆分)生成少量完整长块，沿用同音色速度，顺序合并真实导出 | 每块原文/哈希/计数、真实音轨、导出文件、拼接映射与最终实测字幕；未听不能填听审 |
| 装了字体，正文仍回落成宋体 | 字体未加载或容器没有继承。检查FontFace等待，以及根层、玻璃容器、字幕层的fontFamily；精确补声明，不重配音 | 当前渲染中的中文笔画、最长字幕和字号层级；安装文件存在不能替代看成片 |
| UI入口截半行、PPT底部越界 | 对放大源片继续按旧坐标裁切，或先放大整页再读细节。按真实源尺寸重新映射；先contain完整页面，再局部推近 | 修改段首中尾、切点前后、整页四边与安全区；不要只看中心截图 |
| 备注摘录不对应 | 摘录被总结改写，或用了另一页。以PPT原生notes与页ID提取并逐字核对；未录操作不补成成功 | 原文件/页ID、真实摘录文本、当前画面；不推断PPT每个对象可编辑 |
| 代码/关键帧好看，实际播放不对 | 静态检查代替了当前文件动态观察。使用同SHA实际视频，处理播放器seeked/资源加载与Range支持后再播放 | 实际时间、速率、可见运动及对应主段；分段播放、连续视觉、连续听审分别记录 |
| 取帧失败但原视频能播 | 旧FFmpeg参数或过深select表达式。使用当前可用的-fps_mode；大量帧条件用平衡括号树，而不是无界线性相加 | 真正返回码/stderr、实际帧数和逐帧对应关系；失败残留目录不得充成功包 |
| 自填verified或旧报告继续放行 | 制作者声明冒充验收，或内容改了仍复用旧SHA。用[质量门禁](quality-gates.md)提交submitted、当前取帧包、另一审查者逐项/逐卡/动态观察 | 当前源码/素材/视频/取帧/报告绑定；未落实、未审、旧证据、有未关闭问题均不能通过 |

## 只删除一处辅助文字

1. 找到原组件全部调用点，保存已批准版。登记允许改动的图层、区域和半开帧范围；保护文稿、SRT、句轴、声音、镜头时长和无关资产。风格/文字修改不触发TTS或ASR。
2. 优先在源组件移除对应文字。用户明确要求移除“静帧/阅读”等辅助提示时，在质量方案保留真实static_reading/still身份，并按quality-gates的still_label_override绑定原指令证据；不把步骤标题伪称静态来源标识，不扩大成去掉隐私遮挡或伪造连续操作。
3. 静态背景可分别从当前无字组件渲染清洁区域，再在准确帧段替换。该区域必须不含随时间变化的必要内容；有动态内容或复杂叠层就重渲染受影响段。禁止模糊/涂黑文字来假装删除。把源片、脚本、清洁渲染及区间留在项目证据中。
4. 时钟不变且声音不变时，可直接复制原成片AAC音频流，比较提取后ADTS字节哈希；若重编码声音则比较实际采样并说明损失。不重新生成“同音色”来代替原轨。
5. 逐个看修改段首中尾和进出切点，确认无残字/接缝且正文、标题、字幕不动。视频重编码后不声称其它像素字节一致；区域外相似度只作辅证，不能证明审美或听感。
6. 新SHA重新收集证据并走适用门禁，不搬旧通过、不编辑状态躲检查。动态复核可连播相邻原速段，在相应区间保留真实观察，避免每段重新导航/加载；未执行的连续视听按实记录。没有新缺陷，不额外探索新设计或重跑无关检查。

## 封面：保留已有效的制作方式

参考图的层级、配色、字型重量与倾斜标签可作为设计输入，不能顺手复制其播放量、时长或不适用的产品标识。使用可用图像生成工具制作用户要求的设计字与画面；字型风格以本轮要求为准，不把一次超粗字体变成所有视频默认。成品出现后核对标题逐字、裁切、安全边与实际宽高比例，不能把提示词中的4:3当输出证据。输出尺寸可能与期望像素不同：如比例已正确、清晰度足够就报告真实尺寸，不为凑宣传参数反复生成。保存选定原图和最终提示词到项目，封面修改不重开已批准视频。

## 项目路径与恢复

每期使用[项目索引模板](../assets/项目索引模板.json)，将inputs、edit、audio、captions、evidence和deliverables的真实位置写在项目内。恢复时先读索引和最近交付清单，再查文件存在与哈希，不从临时截图名猜最新版。

- 通用模板使用相对路径；实际绝对路径、本期产品名、账号、声音、PPT、录屏、截图与历史报告留在项目或skill的private目录。
- 记录旧成片、新版本、批准脚本、SRT/实测轴、原声音/合并轨、可编辑工程、当前证据包、独立报告、导出验证、封面和提示词的位置。
- 历史交付证据只证明当时版本。skill规范/脚本更新后旧workflow可能变stale：保存它，按resume/revise重新核对实际受影响内容，不能重写历史来制造新通过。
- 对外PR仅同步审查过的通用规则、代码、合成测试，以及用户明确要求公开的文字钩子库；private本机索引和本期媒体不上传。完整文本库的来源身份不因公开而改变。
