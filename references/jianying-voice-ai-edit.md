# 可选剪映整段配音与实测字幕

先按 [安装与首次使用](installation.md) 说明配音路线并确认需要。已有声音选 existing；不需要配音选 none，跳过剪映、TTS和相应声音校时。没有桌面控制工具时交整段TXT并提供手动导出步骤，不能声称自动化已完成。音色、额度和账号条件以当前版本为准。

## 1 整段输入与字幕分层

- 配音输入：保留自然标点、术语、数字与原意的完整口播 `narration_text`。只归并段落空白，文本对象数量为1；“一个片段”不要求把所有自然句标点删成语病长句。
- 显示字幕：导出真实声音后再依语义分成cue/SRT，仍执行最多两短句、句末问叹号等规则；不能用这套字幕限制去拆配音输入。
- 定稿锁定并确认保护项后，用 [准备脚本](../scripts/prepare_voice_text.py) 生成TXT和输入清单。不要从已去标点的碎字幕自动拼回文稿。最小源结构如下：

```json
{"script_status":"final","revision":"v1","narration_text":"这是保留自然标点的完整定稿。下一句仍在同一个文本片段中。"}
```

```bash
python3 scripts/prepare_voice_text.py /absolute/path/定稿.json /absolute/path/整段配音_v1.txt
```

输出 `整段配音_v1.voice-input.json` 记录源稿哈希、文本哈希、1个对象与1次计划生成。它不证明UI已导入或声音已生成。当前用户要求先审稿时，必须先获得对应稿件版本确认；已授权继续不反复求批。

## 2 固定操作顺序

先读 [已验证UI路线](jianying-ui-recipe.md)，按照该路线执行，不每次探索全部菜单。固定业务步骤如下：

1. 复用本期配音工程，首次创建专用工程与恢复副本；读取当前状态，核对是正确项目、正确文本片段，不覆盖用户其他视频。
2. **文本→新建文本→默认文本右下“＋”**，只创建一个文本片段；选择右侧“文本→基础”的实际内容编辑区域，全选并一次粘贴完整TXT。已有正确片段就复用，不再添加。
3. 从当前文本内容核对首尾、关键术语、字符完整性与片段数量。禁止导入分句SRT供朗读，禁止逐句粘贴建轨；不要为整段配音制作文字样式或逐句拉伸片段。
4. 点击右侧“朗读”。沿用已确认音色/速度；首次未指定时只做一次少量代表内容的音色选择，不每轮重新选声。当前版本实际参数为准，不虚构速度档位。不要在生成后再叠一次音频变速。
5. 仅对这个完整文本片段点击一次“开始朗读”。等待生成状态结束并出现真实连续音轨；观察应用是否自动延长声音或文本。片段原先3秒不代表朗读只能3秒，先看实际结果，不先逐句拖时长。
6. 导出本次完整朗读。已验证路线为右上“导出”，关闭视频导出、开启音频导出，采用已验证可用格式；填写本期输出名/目录，导出完成后检查真实文件。专用工程只有本段声音，避免其他声音混入。
7. 返回当前Agent完成真实音频校时、按语义分句字幕及AI剪辑。默认不再回剪映逐句排空。若当前版本实际限制整段字数或禁止一次生成，记录可见错误/限制并停止依赖操作；不能静默回退成逐句TTS。继续不依赖它的工作，需要改变整段要求时才向用户说明。

发现错读/切尾先定位，判断是输入、音色、生成还是文件范围错误，再修受影响部分；不得为换字体/画面重新生成全轨。确需重生时保留已确认声音与源稿版本，完整文本再次生成属于明确纠错，不当作默认逐句生成路径。

## 3 Computer Use 提速协议

- 同一应用与工程持续绑定。通过当前宿主的应用/窗口清单定位已安装的剪映主程序；不同版本和系统不复用旧路径或歧义标识。
- 优先当前AX可用元素；Qt控件若AX点击没有生效，按当前截图定位实际内容区域。成功路径记在UI配方，不对同一失效AX点击持续重试。元素编号/坐标不跨状态硬编码。
- **确定的短批次＋末尾读取AX状态放在同一个CUA调用。** 例如已确认编辑区后的聚焦→全选→粘贴→取状态；遇到未知弹窗、焦点变化或新布局就结束批次观察，不盲串整条流程。
- CUA的状态读取自带等待，不在每次操作前后加固定sleep；生成等长任务在得到进度状态后处理独立本地工作，再检查进度。不要紧密轮询不变AX；有明确视觉缺项才补截图。
- 窗口/面板切换后重取状态，批次末核对结果；截图用于初次定位、实际文字/选声/生成/导出等关键状态，AX足够时不重复取全屏。
- 整段一次粘贴、一次生成、一次整轨导出。音色/速度和已完成文件按本期版本复用；没有新问题不重新打开候选、生成或导出。等待超时先查是否已经提交/完成，不盲点第二次。
- 不并行向同一剪映窗口发输入；本地文件准备、元数据与独立素材工作可在生成等待期间进行。
- 关键节点留恢复点：文本哈希→音色/速度→生成完成→导出路径/哈希。每步第一次失败先换表征重看，一次针对性修复仍失败就记录具体阻碍/换已验证路线，避免菜单遍历。
- 记录 `ui_calls / observations / retries / generation_wait_seconds / export_wait_seconds / local_processing_seconds / listening_seconds`。以同稿同音色比较耗时与错误率，未对照实测不承诺提速倍数。必要听审不以提速名义取消。

## 4 导出后校时与必要的本地整理

1. 先验证实际文件存在、非零体积、真实音轨、时长、采样率/声道及完整解码。MP3保留原件，可用ffmpeg解码为一致规格的PCM工作副本，不能改标签冒充变速/重采样。记录“剪映原生音频导出”或“剪映视频导出后提取”，不要混称。
2. 整段连续回听，对照冻结文稿检查漏句、重复、术语、吞字、切尾与异常停顿。ASR/强制对齐仅辅助定位；确认稿不被识别错词覆盖。未完整听审就明确范围。
3. 优先直接保留自然连续主轨。只在听到不合理长空白、明确删句等情况修实际区间；静音检测是候选报告，不能自动删除全部静音或天然呼吸。
4. 需要处理时，在本地按已听审的采样区间使用 [音频组装脚本](../scripts/compact_voice_audio.py)，保留原PCM样本、速度与源/成片映射。脚本仍支持旧工程分句文件，但新配音默认输入为一条完整朗读；不得因此恢复逐句UI拖动。调用前读取该脚本接受的manifest/帮助；`range_reviewed`只有实际回听后才能填true。
5. 从最终真实主轨建立 `timing_source=measured`、`audio_source` 与逐句 `start/end`，按 [字幕规范](script-subtitles.md) 生成分句SRT，并由同一时间数据驱动镜头、字幕、声音事件。没有真实声音时只能交明确标注的建议轴；不按字数比例冒充实测。
6. 已有1.1/1.2倍TTS主轨在合成器默认1倍，不二次加速。删除台词联动声音、字幕、画面、音效与后续时间；风格改版保护声音。

## 5 验收与恢复

- 输入：当前冻结稿、整段TXT及哈希、**一个文本片段**的实际UI证据。
- 生成：实际音色/速度、一次完整朗读的记录、真实连续音轨；不是打开朗读面板就完成。
- 输出：真实可解码音频、来源/范围/时长/采样信息；实测轴与最终显示字幕逐句一致。完整听审范围单独记录。
- 配方版本与本机App版本、界面差异、耗时分解、失败恢复点写入本期状态，不能把旧缓存或计划清单当音频证据。
- 原生预设/透明字幕只在当前UI实际核验。无透明导出时可在当前合成引擎近似重建，并标身份；alpha仍需解码、明暗底叠加与导入检查。配音用完整长文本不应当作最终整屏大字字幕交付。
- 锁屏、用户接管、登录/收费提示或控制失效时保留现有真实产物与恢复点，继续独立工作，不能报已完成；不自动同意购买或改账户设置。
