# 视频网感文案与字幕生成规范

用于根据用户的主题、素材和已确认内容，选择口播、字幕与短视频叙事方案。机制来自参考拆解后的创作推导，不是平台算法规律或播放量保证。这里提供通用创作方法，不分发第三方参考原图或私人研究记录。

## 1. 从观众的任务推导文案

观看者至少要迅速理解：**这和我有什么关系、继续看能得到什么、为什么相信、下一步怎么做**。据此设计注意、理解、证据、行动四个环节，而不是随机抽一句“爆款开头”。这四个环节是写作检查视角，不是声称经过实验验证的注意力模型。

- **相关**：具体人群＋正在做的事＋真实阻碍；“面向小白、提高效率”不足以确定一句话。
- **值得看**：一个清楚的收益、一个真实反差，或一个后文确实回答的问题；收益与素材能力边界一致。
- **看得懂**：每段推进一个动作、原因、证据或判断，语言像对一个目标用户解释。
- **信得过**：主张有画面/声音/事实支持，结论不超过展示范围；成品好看不自动证明全流程稳定。
- **做得到**：结尾给与本片收益一致的一项主要行动，不在最后突然转推无关对象。

“强冲突、共鸣、反常识、悬念”属于注意力的不同入口；“故事、清单、实用技巧”等属于内容形态。两者可以组合，不把参考中的4类、9类、300个句式当互斥、完备或必须轮换的分类。

## 2. 按输入状态选择写作路径

| 用户输入 | 先做什么 | 可交付与边界 |
| --- | --- | --- |
| 只有主题/想法 | 确定目标人群、任务阻碍与主要目的，列能证实与待补的主张 | 交有条件的文案方案/初稿/建议画面；不能说已看素材、已跑产品或已得到效果 |
| 无声操作录屏 | 看关键操作、等待、失败、结果，标源时间；选最值得讲的一项任务 | 按画面生成旁白；不做伪ASR，不强行讲未录制步骤 |
| 录屏＋已有口播/配音 | 核对原声、逐句文本、实测时间轴和保护项 | 画面跟声；先区分只修断句、允许润色、还是允许重配，不擅自重写已保护旁白 |
| 用户给草稿 | 找事实空缺、铺垫、重复和不自然表达，保留认可内容 | 定点改稿；可给不同机制的开头，不为“网感”换掉原意/语气 |
| 已定稿，只要SRT | 保持原文、语义断句、校时、格式验证 | 不重新发散选题或改钩子；首尾问题可提示，不越过保护项自动改写 |
| 只要宣传简介/标题 | 提炼受众、能做什么、步骤和收益 | 按所需长度直接交短文案，不扩张为全片脚本、配音或视频制作 |

信息缺项先利用现有上下文，只询问会改变方案的关键问题。能独立写的先写；素材没有证明的内容标待补，不编造成功、体验、用户故事或优惠渠道。

## 3. 决定主要目的与正文路线

内部写作顺序：**素材事实 → 人群任务/阻碍 → 一个主要目的 → 可兑现收益 → 正文路线与证据 → 开头候选 → 逐句口语稿 → 字幕与引导**。先知道正文交付什么，再决定承诺；这是创作顺序，成片仍从钩子开始。

主要目的从发现/理解、跟做/体验、判断/信任中选一个，其余辅助。不要把扩大覆盖、解释产品、催转化和表达个人价值观同时抢进前3秒。教程默认围绕观众能完成的任务；转化要说明适合谁和怎样使用；人物信任只能使用真实经历/判断，默认不增加真人主持或数字人。

| 素材条件与任务 | 推荐正文路线 | 常配开头 | 排除条件 |
| --- | --- | --- | --- |
| 有与痛点直接相关的清楚成品 | 结果预览→输入/限制→关键过程→验收/使用→引导 | 结果带路＋具体问题 | 不拿漂亮但无关的PPT做开头；不把最佳一次当稳定表现 |
| 有完整可复现的操作链 | 痛点→准备→必要动作/判断→成功状态→引导 | 场景共鸣/直接收益 | 不机械凑三步，不删必要前提或成功确认 |
| 有真实失败和修复后对照 | 症状→定位原因→修正动作→前后验证→引导 | 问题诊断/有依据的反常识 | 无失败证据时不伪造踩坑，不承诺单一方法包治所有情况 |
| 有同条件的两套结果 | 同一问题/输入→路径A/B→同维度证据→适用条件→引导 | 真实反差/选择问题 | 没有可比输入、版本或评价依据时不做胜负结论 |
| 有真实经历或明确用户痛点 | 具体处境→阻碍→真实选择/做法→结果/边界→引导 | 场景共鸣/真实故事 | 不移植作者的年资、朋友反应或虚构一段亲身经历 |
| 有可分解的要点，缺完整演示 | 问题→少量核心原则→实例/示意→可执行检查→引导 | 检查清单/具体疑问 | 列表条数按真实内容计数，不硬凑数字；示意不冒充产品操作 |
| 主题确实关联当前热点 | 相关事件→核实事实→用户影响→实际例子→边界/引导 | 与任务相关的反差/问题 | 热点仅作表达辅助；未经核实、已过时或无关时弃用 |

同一素材可能支持多条路线。先按本期目的、证据充足度和受众理解成本选主路线；不强行拼成一条混合公式。可用已确认的单条方案，不额外制造多方案审批。

## 4. 钩子选型与前三秒

教程/推广叙事默认建议：**前3秒交代与目标任务有关的痛点或结果**。已确认首尾和其他体裁按本期需求覆盖。痛点可以是不会做、易出错、重复劳动或难讲清价值，不等于制造焦虑；结果前置也要说明它解决什么阻碍，不先放长Logo/自我介绍。

| 入口机制 | 使用条件 | 本技能原创示例（按真实材料改写） | 后文必须兑现 |
| --- | --- | --- | --- |
| 场景共鸣 | 知道受众具体卡点 | “活没少干，答辩却没话讲？” | 如何整理贡献/讲稿，而非只换一张漂亮封面 |
| 目标与阻碍的冲突 | 有真实矛盾及解决过程 | “模板没少改，重点还是讲不清？” | 从内容组织到结果的具体改动，不虚构对立人物 |
| 认知对照 | 有可靠反例或前后证据 | “字幕难跟读，问题可能在断句” | 实际断句对照与适用原因，不能为了唱反调否定常识 |
| 可回答的疑问/悬念 | 有一个明确、值得知道的答案 | “这段配音哪里别扭？听这个停顿” | 尽早指出停顿及修法，不一直说“看到最后” |
| 结果带路 | 有相关成品且足以看清 | “答辩没话讲？先看这页讲稿” | 展示真实讲稿及如何得到，不借无关成品欺骗 |
| 清单/低门槛开始 | 有少量可执行检查项 | “教程开头卡住，先查这三处” | 真正数得出的三项和执行办法，不把清单数字当效果数据 |

需要新稿时，通常产生2–3个机制不同的短开头，再自主推荐一个：比较相关度、理解速度、素材证据、承诺可兑现度。三个同义替换不算不同方向；不是每次必须给用户三选一。用户已有开头或只要局部修改时沿用确认方向。

预估字数只用于试读，最终按实际语速/配音检查前3秒：观众能听清主要痛点吗、画面有对应对象吗、是否堆了两项承诺？长开头先改写，不靠吞字、整轨加速或把字幕切碎硬塞。未配音时标“建议时长/待实测”。

每项开头承诺建立对应：**承诺 → 源素材/事实 → 正文兑现句/镜头 → 未证实的边界**。钩子之后尽快给第一份实质信息或证据，主要问题在结尾引导前回答；不能把并不存在的答案藏到结尾。

## 5. 正文的口语与信息节奏

- 先写一个完整意思，再变成能开口讲的话。用明确对象和动作：上传什么、在哪确认、看哪个结果、什么情况下要重试；少用“赋能、颠覆、全链路、极致高效”等空泛评价。
- 降低的是目标受众的理解成本。面向开发者等专业用户时保留必要术语和条件，不为了让所有人听懂删掉真正影响操作的内容。
- 每段至少推进一项：新动作、原因、证据、必要判断或边界。只重复“很简单/很强大/太好用”的句子删掉；操作字幕不逐项朗读无关菜单。
- 选择本片最值得记住的少量核心点，让例子与录屏服务它们。多项细节按操作依赖展开；不能为压缩信息删掉关键前提或失败检查。
- 用自然因果和指代串起镜头：先看什么、核对哪里、确认后怎样、结果怎么用。不要每句都“接下来、然后我们再来”，也不靠连续问句假装互动。
- “网感”来自具体处境、信息落差、节奏和可兑现的表达；不用四字碎句、夸张语气词、无意义热梗或密集叹号制造。
- 数字/比例/耗时/价格/成功率/用户数要有来源。步骤数可实际计数；“95%的人都错了、3秒学会、必火、全网第一、马上下架、零成本、人人适用”等表达不因出现在参考中就获得事实依据。
- 反常识必须保留适用条件和证据；参考里的医疗、财富等示例只研究写法，不移植其事实结论。争议不替代论证，紧迫感不靠虚构后果。

## 6. 口播、字幕、画面文案各司其职

| 层 | 任务 | 约束 |
| --- | --- | --- |
| 口播稿 | 连贯解释、交代动作与判断 | 保留完整段落和自然标点，剪映放进一个文本片段一次朗读；定稿后不因美术改版偷改台词 |
| SRT字幕 | 跟随实际声音，帮助读懂 | 每条最多两短句，通常8–26个中文可见字作起点；句末不加标点，问号/叹号例外；两短句间可有一个逗号；避免四字及更短碎片，必要例外按cue记录 |
| 重点字卡/标签 | 补充定位、结果身份或关键关系 | 可以是短词，但不冒充完整SRT；不把每句旁白再复制成一张卡，不新增未经证实的收益 |

字幕优先按语义、停顿与阅读负担切分，不按固定秒数、逐字或每四字切。工具名、数字与单位、修饰语和被修饰对象尽量不断开。较长一句拆成相邻cue后，声音仍可自然连续，不要求每换字幕就人为加气口。

上表钩子示例是口播，不是已定时SRT。口播的“问句＋解释”可按实际声音拆成两个完整cue；不要把内部问号、三句台词或四字碎片原样塞进一条字幕。具体标点仍按SRT工具规则处理，不能为通过校验改动受保护的口播文本。

已有声音时以最终实测音轨定轴；去空白/删句后重建SRT与镜头。无声音时只交明确标注的建议轴。主文本、cue ID、SRT与镜头对应必须同步，ASR错词不覆盖确认稿。生成与校验见 [SRT工具规范](script-subtitles.md)。得意黑、字号、安全区和镜头动效沿用现有规范；网感改稿不取消丰富剪辑，也不把每条字幕强制加声音。

## 7. 结尾、交互与交付检查

结尾必须引导，选一个与主要目的相符的动作：跟做/体验→让观众拿自己的真实任务试；复现教程→收藏步骤/模板；问题解释→邀请说出具体卡点；对比→按条件选择并验证。没有已确认资料或链接时不编造“评论关键词自动领取”，不堆关注点赞收藏转发四连。

新稿先交“推荐方案＋可修改口播＋画面对照/缺项”，按用户反馈定点改；明确先审稿就等待，已授权全权执行则自行选定继续。模板见 [文案方案模板](../assets/文案方案模板.md)，简单请求内联表达即可，不强制额外文件。

交稿前检查：

1. 目标用户能否马上认出具体场景和阻碍；前3秒钩子是否已在试读/实测中成立
2. 开头承诺是否有源证据、正文兑现位置和限制；每段是否推进而非拖延
3. 正文路线是否匹配素材，产品/数字/经历是否真实，缺项是否明确
4. 大声读是否顺口；目标外行能否复述“给什么、做什么、得到什么、何时不适用”
5. SRT是否最多两短句、无机械四字切分、标点合规；字幕、声音、画面是否同一版本
6. 结尾是否只要求一个主要动作，并接得上这条片已经交付的价值

未真正让目标外行试读，只能记录“代理复述自查”，不能冒称通过用户测试。未经发布验证不承诺完播/转化提高；需要比较开头时保留正文、声音、片长等尽量可比，数据和观察时间确实可见才记录，不自动发布或创建监控。
